# Private browser transport foundation

The optional owned-server path is not exposed yet. Existing service mode and shared profiles remain unchanged. The planned owned path uses a separate environment and persistent profile, a directly supervised child process group, inherited bootstrap/browser descriptors, and actual authenticated readiness. It must never adopt or stop an existing shared daemon implicitly.

## Qt transport evidence

An isolated Qt 6.12 experiment creates a hidden `devToolsView` without remote-debugging TCP flags. A MainWorld user script installed at DocumentCreation, before assigning `devToolsView`, can intercept the native `InspectorFrontendHost.sendMessageToBackend` and `DevToolsAPI.dispatchMessage` boundary before frontend initialization.

`ui/browser/private-cdp-bridge.js` is an internal foundation, currently not wired into the product. It remaps every frontend and server request into one monotonic physical-ID namespace, restores the original IDs, routes frontend responses back to their dispatcher, and queues server responses privately. Events retain normal frontend delivery. Pending requests, messages, queued output, and chunk assembly are bounded. Closing retires pending state; it never replays a request.

The bridge contains no console or status output. Product integration must carry drained raw messages exclusively through the inherited private browser descriptor. The inspected application page must never receive this script or a native bridge. Each owner must fence it by environment, profile, lease, thread, tab, and actual target identity, and release it when that owner disappears.

`tools/test-private-cdp-qt` builds its standalone fixture and runs it only in private rootless Podman with read-only inputs, no network, and disposable fixture storage. Run long checks through a transient user service. The experiment sends concurrent `Runtime.evaluate` and `Target.getTargetInfo` commands through the actual Qt channel. Both original request IDs are restored, the returned synthetic title matches, and the actual target ID equals the page's `devToolsId`; the frontend reports no wrong-ID protocol error. Separate pure-boundary tests exercise collisions between frontend/server IDs, out-of-order responses, event delivery, chunk assembly, bounds, and release. Synthetic chunk tests do not establish that Qt's large-message transport emitted chunks: a 1.2-million-character actual response arrived through the ordinary dispatcher.

## Remaining integration

The raw transport is not complete native browser parity. The pinned native source is `32a0531748c44b25072d7495ce0b9bd7e9450a87`, especially `DesktopBrowserHost.ts`, `CdpRelay.ts`, and `GuestInput.ts`. It includes owner-scoped screencast/focus/painting behavior, child sessions, detach cleanup, and Electron-specific unfocused input/reload handling. Qt equivalents require actual behavior proofs.

The owned launcher, descriptor codecs, and actual guest/inspector admission now connect to the existing product Pool through a private writer and target/session routing. The owned-environment controller, global authoritative preview observer, public mode selection, and remaining native permission/dialog/viewport behavior are still pending. Guest creation must react to authoritative opened events before an open RPC completes, and attachment must be announced only after acquiring the actual target lease. No UI capability should be advertised from this foundation alone.

Bootstrap credentials and bearer snapshots remain in process memory; the launcher does not persist them. Dropping the owner stops and reaps its child with bounded group termination and retains the persistent profile.

Fourteen focused private-container functions pass, including 44 actual native rotating-token fixtures, expiry and explicit-refresh single-flight behavior, failed-renewal invalidation, retained-secret zeroization, late-result rejection, runtime/path validation, actual current/previous-bucket OAuth/RPC, real RPC socket identity, and private profile-lock/shutdown behavior. It does not apply that limit to the outer escaped NDJSON envelope. The future descriptor parser needs independent framing headroom, including JSON escaping and UTF-8 byte accounting. A raw debugger response above the low-level limit retires the bridge; exact unbounded-response behavior is not claimed.

The ordinary hidden Qt frontend initializes debugger domains, target discovery, and metrics instrumentation of its own. The automation-only minimal mode now suppresses every frontend-origin request from DocumentCreation and leaves its promises unanswered. Eight pure-boundary fixture groups pass, including minimal-mode suppression. Opening real DevTools must retire the automation lease and replace its inspector rather than enabling frontend traffic on the existing lease.

Composition remains gated on per-lease target/session filtering, dedicated-descriptor wiring, and actual input/focus behavior. Copying the pure factory and suppressing hidden frontend traffic do not by themselves prove a complete CDP endpoint.

## Parent-side descriptor adapter

`desktop_browser_ipc` provides two distinct directional socketpairs: events go from the parent to the server's input descriptor; commands go from the server's output descriptor to the parent. Child sources are duplicated above standard-I/O slots with `F_DUPFD_CLOEXEC`, retained in the command owner, and made inheritable only in the forked child. A real exec test verifies both directions and unchanged parent descriptor flags. Bootstrap startup now uses the same high-descriptor mechanism and its actual CLI readiness proof still passes.

The parent decoder follows the actual Effect 4.1.2 `decodeText` → `splitLines` → nonempty-line pipeline. It preserves streaming lossy UTF-8, initial BOM handling, CR/LF/CRLF and EOF behavior. Invalid JSON or command-schema lines are ignored without poisoning later valid lines. This is deliberately separate from the server input NDJSON decoder, whose error behavior differs.

Five focused Rust functions pass, including 346 native schema projections and 242 actual parent byte-stream cases, directional/cancellable I/O, exec inheritance, and framing cancellation. Numeric-overflow cases preserve opaque message strings, ignore stripped overflow fields, and reject nonfinite coordinates. The fixture is native JSON.stringify output, so the comparison normalizes signed zero only in its test snapshot; production pointer values are unchanged.

The adapter separately bounds an outer wire record at 256 MiB of UTF-8 bytes. Event encoding counts before allocating its output buffer. Native CDP message and serialized-payload limits remain separate. Overlong records retire buffered state without replay; the cap and cancellation differ from an unbounded native pipe. Lossy UTF-8 can expand invalid bytes in memory, and accepted strings/JSON projections also allocate; this is bounded transport work, not a claim of allocation-free processing. No maximum-size end-to-end memory claim has been proven yet.

The adapters now connect to the opted-in internal product Pool, including actual target/session admission and private guest wiring. The authoritative owned-environment observer and public activation remain pending; browser descriptor fields are still omitted from default product launches.

## Lease admission foundation

`browser_automation::Registry` separates environment/profile, the actual spawned guest Session ID, thread/tab, and the actual inspector attachment instance. The spawn owner registers the guest; the trusted inspector creation path registers the expected attachment before asynchronous target probing. Admission compares its view `devToolsId` with its actual private CDP target response. The product Pool now registers each actual spawn and allocates each inspector object's nonce before its open command. Its trusted QML inspector supplies the view ID and real private target response; the generic proof constructor alone still does not authenticate an untrusted claim.

Seven pure policy cases pass: matching target/current attachment, delayed-probe rejection, stale guest/inspector/error retirement, unrelated-environment isolation, tuple-key separation, exclusive physical-target ownership, retirement without resurrection, and refusal to silently retarget a live attachment. Retired leases are returned for cancellation outside global locks. Those original cases establish local admission rules. Separate actual Pool and Qt tests now exercise the producer and scoped CDP path; they do not establish all native browser behavior. Normal native `release` resets the relay while retaining the debugger attachment; it must not be confused with retiring the physical inspector.

The owned supervisor now retains a private Zeroizing rotating bootstrap secret and derives the exact native 12-hour-window HMAC using the already locked `hmac` crate. Borrowed credential fields serialize directly into private bootstrap IPC without a secret-bearing JSON Value. New admissions use `fresh_connection`: an unexpired bearer is reused; expiry-directed renewal and explicit refresh share a per-owner flight. Failed renewal invalidates current admission without rewriting snapshots already held by callers. Shutdown actively zeroizes the retained secret, cancels waiting refresh admissions, rejects late success, stops the actual child, and releases its profile lock. Existing Connection snapshots and their actual socket identities are not relabeled or replayed.

Before exposing owned mode, connect this fresh-admission API to the owned environment and actual RPC-session lifecycle, prove event/command target-session isolation, and wire authoritative preview lifecycle and private guest descriptors. Abnormal descendant cleanup after an already-reaped leader remains separately qualified; an unknown/reused numeric process group is never signaled.

## Complete native Host intake and Qt composition proof

`ui/browser/native-browser-host.js` bundles the actual pinned `DesktopBrowserHost.ts`, `GuestInput.ts`, `CdpRelay.ts`, their desktop-browser schemas, and Effect 4.1.2. `tools/build-native-browser-host.mjs` checks all five upstream source hashes and the exact Effect/Rolldown versions before building. Its provenance manifest records every bundled dependency input hash. The only Node platform import is the actual Node 26.13.0 string-domain POSIX path implementation, extracted by `tools/build-node-path-boundary.cjs` under an exact source hash. A separate private differential experiment matches 969 string-input cases against that Node runtime; this does not assert general Node error-message compatibility. Upstream human copyright and MIT permissions are retained in `licenses/`.

The small scoped facade delegates attach, detach, visibility, command handling, and download placement to the actual native Host. It collects the real native event, painting, and pointer streams. Its output queues have a 4,096-record limit, with a separate 256 MiB UTF-8 event-byte budget; overflow retires the scope with a static error. These are wrapper cancellation/resource limits, not native behavior or a maximum end-to-end memory guarantee. Native upstream queues and intermediate objects may allocate independently.

`tools/test-native-browser-host-qt` copies its C++/QML inputs, private bridge, generated Host, and source manifest into a unique retained evidence directory before compilation or execution. Runtime runs only in rootless Podman with read-only inputs, private temporary state, and no network. It uses the actual trusted Qt inspector and an unrelated page in the same profile. Two simultaneous native screenshot requests produce the owned hidden page's 640-by-480 PNGs with the expected pixel color, while the real low-level screenshot count never exceeds one in flight. Native focus emulation turns on and returns to idle off. No unauthenticated TCP debugging port is enabled.

This composition proof does not establish Qt keyboard/pointer/reload adapters, download placement, per-session privacy, product guest descriptors, preview-observer creation, or owned-environment integration. The fixture supplies only the webContents methods exercised by these screenshot/focus paths. The generated Host is installed only in the opted-in internal product inspector; its presence does not advertise browser capability or select owned mode.

## Required Qt target/session isolation

An actual private two-page Qt experiment confirmed that the pinned native relay's page-session passthrough is broader than its virtual browser root: page-session `Target.getTargets` exposed the unrelated page and inspector, and page-session `Target.attachToTarget` could attach that unrelated page. The virtual native browser root already returned only the owned page. The route remained unselected throughout the experiment.

`ui/browser/qt-target-scope.js` therefore enforces an additional Qt platform boundary below the unchanged native relay. Raw browser-wide commands, discovery, context creation/disposal, target enumeration, message tunneling, foreign target actions, and unknown physical sessions are refused. Native virtual-root target queries remain unchanged. The boundary does not issue a profile-wide query and filter its reply, fabricate acknowledgments, or inspect/rewrite opaque Runtime parameters. A real scoped `getTargetInfo` response must still name an admitted target.

Flattened iframe/worker attachments from an admitted physical parent establish child ownership. Explicit attachment is restricted to known owned targets; descendants and their sessions are removed together on detach. Unknown-session events are dropped. Physical session/target mismatches, resource overflow (4,096 entries), and close fence later admission. Scope creation and destruction still require the actual guest/inspector owner; this module is not an identity producer. Other child target categories and nonflattened sessions remain qualified integration gaps.

The private boundary proof covers foreign browser/target/session refusal, unchanged opaque Runtime objects, related and manually attached child sessions, subtree invalidation, target mismatch, bounds, and close. The real Qt composition proof retains captures/input/focus behavior, refuses browser escape requests before physical dispatch, and creates an actual owned Worker: its emitted physical child session can run `Runtime.runIfWaitingForDebugger` and read `self.name` as `owned-child`. This necessary Qt safety-boundary difference is explicit; it is not byte-for-byte page-session passthrough parity. Product activation and dedicated guest FD lifecycle remain pending.

## Existing product Pool and inspector lifecycle

`browser_guest::Pool` now uses the actual existing browser-render process and profile for both selected pages and background backend pages. Opt-in source binding has a separate native-event callback; it never falls back to the UI callback. A real Session ID is allocated before spawn. The Pool registers each inspector's fresh constructor nonce before any QML probe, passes it to that actual object's constructor, and admits only the returned matching private target proof. The component's native Host starts only after the Rust admission acknowledgment.

Every private command/event carries that immutable inspector nonce and current lease. Retired-tab callbacks, delayed expected/proof/close events, and wrong lease IDs cannot replace or retire a successor. Scope closure cancels only the actual source; unrelated guests remain usable. Active backend turn state is retained before a page exists and latched into admission. A per-guest ordering guard places the admission acknowledgment before concurrent commands without making endpoint shutdown wait on a global lock. Command/event CDP strings stay opaque, including unknown nested object order.

Background ensure creates the actual WebEngineView without selecting or focusing it. Showing that same tab reuses its view, target, inspector lease and profile. Native painting temporarily keeps a hidden view rendering at zero opacity. The private QML component has one inspector pump in flight, and all private data travels over the inherited socket. Public stdout continues to carry only existing typed navigation/frame metadata.

The latest private runner passes five functions with no ignored cases: three exact filtered unit cases (descriptor admission, stale/unrelated-source fences, admission/turn ordering) and two physical integrations. The product integration launches the actual frozen Cargo CLI and browser library, opens two server-runtime pages through the exact owned server `0b9a5d3` (SHA-256 `23b9f821ddc2d3da7597ff9f65cbb3ab7daa6e5eb84c1887301b1977595a977c`), and observes distinct actual targets in the same profile guest. Actual selected-frame PNG pixels remain blue after a red page opens in the background; selection metadata stays on the first tab. Hide/show preserves its exact target and lease. The second integration waits for actual document loading and authoritative asynchronous navigation state. The wrapper's separate private boundary test covers opaque messages and pending cancellation using explicit fake platform boundaries; native algorithms are exercised by the physical integrations.

This is a product route proof, not a completed public owned mode. The controller still needs global authoritative preview observation and fresh RPC permission admission, and the UI must use the same Pool route. Existing server-surface/report guards and duplicate-action behavior need owned-only integration. Notifications/clipboard decisions, other dialogs/download placement, full keyboard/pointer fidelity, and per-tab hidden viewport/zoom layout remain open. Resource caps and additional copies also remain qualified: no maximum-size end-to-end memory acceptance is claimed.
