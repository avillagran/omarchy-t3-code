# Native Electron guest foundation

The optional owned browser is being evaluated with Electron 44.10.1 and the actual T3 Code Nightly 4301 BrowserSession, DesktopBrowserHost, GuestInput, and CdpRelay modules. The production Sidepanel still uses the existing Qt guest. These tools do not install Electron or enable a renderer selector.

Native source revision: `4cb6945dc60ed03f567dc5daafd083e52308e82b`. BrowserSession SHA-256: `9e66dd7d6c8d6e376d7f9a35ae1f58d82225fb5a5549781551baaba89adc3f03`.

## Private physical acceptance

`tools/test-native-electron-owned --runtime DIR --services BUNDLE` freezes inputs, verifies every runtime file against the manifest and starts a private X11 display inside rootless Podman with networking disabled, read-only inputs and a private home. A separate Qt application owns the synthetic operating-system clipboard. Neither the host display nor the host clipboard is mounted.

The first passing evidence is `native-electron-owned-8cybzvdd` under the private desktop build cache (result 0). It demonstrates:

- A real `webview` guest using the native preferences: sandbox enabled, Node integration disabled, and context isolation disabled. The sandbox preload confirms the actual sandbox; the document has no require, process, Buffer or native-host globals.
- Real host-webContents, partition/session and DevTools target identity, with actual native attached-event registration before CDP commands.

A DevTools `execCommand('copy')` returns false. These outcomes are preserved rather than converted into automatic grants. The successful explicit native copy operation is a separate tested path.

A second private physical proof, `native-electron-owned-cp68mcf1` (result 0), confirms that Electron's raw page debugger can inspect a different real guest with `Target.getTargetInfo`. ## Actual Qt input-method producer

The GUI plugin now contains BrowserInputItem, a real QQuickItem accepting QInputMethodEvent. T3BrowserPage loads it only for an admitted native-engine frame whose actual focused-frame observation permits native composition. Existing Qt renderers do not load the optional plugin. ## Address-only native crash diagnostics

The official Electron 44.10.1 Linux x64 symbols archive is 146,810,712 bytes, SHA256 `9c497198ec2e5b0c097a5a10434255d26d10e467c6670b3115e4c00df68e0d43`. Its Breakpad module identifier matches the runtime ELF build ID `fc9d8597c41adcdeb85db23812cccfc84a12afd0`. The archive is verified and its electron.sym member is streamed in a private container; no archive tree, process memory, core or minidump is extracted.

The [matching kernel's print_vma_addr](https://github.com/gregkh/linux/blob/v7.2.15/mm/memory.c) reports a file offset. This ELF's executable segment maps file offset 0x3430000 to virtual address 0x3431000, so the repeated file offset0xb1c09f1 maps to virtual address 0xb1c19f1. Official symbols place that instruction in `blink::EphemeralRangeTemplate<EditingStrategy>::RangeOfContents(Node const&)`. Static disassembly reads offset0x14 through its Node argument, matching the reported fault address0x14. The [pinned Chromium source](https://github.com/chromium/chromium/blob/152.0.7977.169/third_party/blink/renderer/core/editing/ephemeral_range.cc) constructs the range from the supplied node. This identifies the failing function; it does not identify its caller or justify changing focus or selection.

Only the existing isolated fixture diagnostic configuration enables [Electron's native stack-printing variable](https://github.com/electron/electron/blob/v44.10.1/docs/api/environment-variables.md). The child keeps its sandbox and hard core limit zero; the application does not start crashReporter. A bounded stderr reader retains exclusively hexadecimal native PCs from recognized stack-frame lines, discards every argument/function/payload string, and continues draining through EOF after its 65,536-byte output budget. The existing typed lifecycle log has its separate 65,536-byte budget. Ordinary native factories do not forward this diagnostic variable. The private sink must be the canonical owned 0700 HOME's native-electron.log, a single-link regular 0600 file opened with O_NOFOLLOW/CLOEXEC.

The immutable private `browser_stack_diagnostics` target passes 2 tests, zero ignored, including mixed sensitive canaries, oversized lines and complete input draining after the output cap. Strict checks cover the library, actual CLI, Manager probe and diagnostic target. These diagnostics do not enable a public browser renderer or alter the native permission policy.
