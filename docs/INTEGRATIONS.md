## Device ownership and observation

T3 owns device discovery, SSH connections, server-side aliases/identity paths, tool installation and lifecycle. ot3 never runs local SSH, adb or installers for these operations. `devices-read` combines fresh native roles, `server.getSettings` and the first snapshot of `subscribeDeviceState {}`. Opening/reading settings never calls `device.list`: even its default read operation can start enabled helpers. `devices-watch` observes the same native subscription, emits bounded public state with environment, origin digest and request nonce, and cancels on reselection, hiding the panel or worker shutdown. Disconnects invalidate UI controls; raw transport errors/config/credentials are not forwarded.

Explicit actions are `hub`, `agent`, `inspect`, `refresh`, `update-tool`, `retry-host`, `test-host`, `host-upsert` and `host-remove`. Hub enable sends exactly `{enabled:true,onboardingCompleted:true}`; disable additionally revokes agent access. Environment agent changes use `device.configure`; project overrides use the existing native scoped settings planner. Browser access also uses that planner. Direct environment patches for agent device access fail with `device_configuration_required`, avoiding lifecycle bypass.

Version inspection requires the fresh native `supportsToolInspection` capability before `device.list {inspectOnly:true}`. Older servers may otherwise ignore the flag and start helpers. Tool updates/retries require native orchestration operate; configuration/host changes require settings write. Plain state needs orchestration read. Hub/agent/host changes are environment-only; native tool inspection/refresh/update remain available within a project selection. The UI must preserve the original mixed-environment agent grant semantics, not require every selected hub to be enabled.

## Concurrency and outcomes

Every action captures an opaque single-use view bound to environment, origin and settings digest. Before dispatch, fresh native roles/settings/state/capabilities and host membership are checked. Per-environment locking rejects overlapping writes inside this worker. The native API has no atomic server compare-and-swap for this whole-array host setting; another client can still change it between the last read and native update, as with the original GUI. Host updates port the original native destination-matching algorithm, preserving each environment's host ID and all unrelated entries; ambiguous destinations fail. Native nullish fallback is lazy, including when an original destination matches and a new destination is ambiguous.

After native acknowledgement, fresh state/settings are read back and requested values checked. A missing acknowledgement or failed readback is `uncertain`; there is no automatic replay. A consumed view cannot be reused. This is not a durable operation journal: the future UI must retain uncertain outcomes through its session and explicitly re-read before offering another deliberate action. A process restart cannot establish that a pending setup was cancelled.

Device reads and actions have separate lazy bounded worker pools, so a slow native download does not block drafts, chat commands or progress reads. Pools allow four concurrent requests each with 64 queued; native lifecycle writes remain serialized per environment. Changing UI visibility cancels observation, not a previously dispatched action.

## Shared transport extension

The pinned `t3-protocol` dependency at `1a616ab6ccb31b689f41ff6f74915e69c780b1a3` has a short ordinary RPC deadline. Native tool preparation can take longer. `vendor/t3-protocol` contains that exact MIT-licensed source plus one additive `Connection::rpc_with_timeout` method. Root Cargo uses a path patch; the original Git dependency/pin remain recorded. `UPSTREAM.json` hashes every original file; only `src/lib.rs` appends the module declaration. No shared checkout or Cargo cache was changed.

The new method reuses the crate's authenticated websocket factory, including DPoP ticket/relay admission. It preserves Effect Request/Exit framing, handles websocket and JSON heartbeats, ignores unrelated request exits, and uses an explicit deadline up to 300 seconds. Timeout sends Interrupt and reports unknown outcome, never replaying. Existing `rpc` behavior is unchanged. This is a local extension, not a claim that the shared library was updated upstream; it can be removed when an equivalent API is available at a verified upstream pin.
