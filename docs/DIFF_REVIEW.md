# Read-only native checkpoint diff review

Parent integration is now present in lib/write/main, backend/panel, activity/file actions and qmldir. Serialized QML fixtures and integrated panel checks pass. The checklist below records the integration contract; richer native features listed at the end remain pending.

Native reference: `t3code-nightly` commit `5a4e9980`: `packages/contracts/src/checkpointDiff.ts` (`ThreadTurnDiff`), `apps/server/src/checkpointing/CheckpointDiffQuery.ts`, `apps/web/src/components/DiffPanel.tsx`, `apps/web/src/components/chat/ChangedFilesTree.tsx`, `apps/web/src/components/diffs/DiffFileTree.tsx`. The **only** source of patch content is the existing `diff` op in `src/write.rs`, which invokes `orchestration.getTurnDiff` for `fromTurnCount > 0` or `orchestration.getFullThreadDiff` for zero. Response is `{threadId,fromTurnCount,toTurnCount,diff}`; `ignoreWhitespace` is an optional boolean on both native RPC inputs and defaults to **true**. It is not a separate file-diff endpoint. Existing `protocol::changes::summaries()` produces `{id,runId,fromTurnCount,toTurnCount,files:[{path,kind,additions,deletions}],additions,deletions}` from completed ready checkpoints; the summary is a hint, not an authoritative patch. Client settings in native `settings.ts`: `diffLayout:"stacked"`, `diffIgnoreWhitespace:true`, `wordWrap:true`, `diffFilesCollapsed:true`; original file tree initially closed.

## Owned pieces and contract

- `src/diff_review.rs`: `present(&native_rpc_result,&checkpoint_summary) -> Result<Value,String>`. Input is **the native result object**, not a wrapped API response. Output `{files:[{path,oldPath,kind,binary,missing,additions,deletions,rows,splitRows,summaryAdditions?,summaryDeletions?}],additions,deletions,fromTurnCount,toTurnCount}`. Each unified row has `{kind,text,oldLine,newLine}`; split row has `{kind,left,right}` with null on absent side. Text is actual Git patch text, never invented old/new file content. Git C-quoted/octal and unquoted spaced paths, rename/deletion/binary metadata supported. Summary paths absent from patch are explicitly `missing:true`. Limits: 2 MiB patch, 256 files, 12,000 lines, 16 KiB per line; hard error rather than deceptive partial success. Split pairs contiguous deletion/addition blocks from actual hunk lines; no fake side-by-side preview.
- `scoped_result(&expected,&action_receipt,&summary) -> Option<Result<Value,String>>`: expected `{requestId,environment,thread,fromTurnCount,toTurnCount}`; receipt is existing `action` envelope `{requestId,environment,thread,result,error}`. `None` rejects stale/other-thread/environment/range/invalid expectations. `Some(Err)` clears display and surfaces error. Do not keep previous patch after a failure or scope switch.
- `ui/qml/T3DiffReview.qml`: required `view:{loading,error,data}`, required `summary`, optional `initialPath`, `diffLayout`, `wordWrap`, `ignoreWhitespace`; signals `closed`, `retryRequested`, `whitespaceChanged(bool)`. Selected file list, previous/next, Ctrl+Left/Right, PageUp/Down, Escape, responsive file dropdown, actual unified/split hunks, context visibility and hunk fold, addition/deletion totals, binary/missing notices. `whitespaceChanged` is **only a request**: host must refetch native diff with the new option. This component neither fetches nor writes Git state.
- `ui/qml/T3Changes.qml` now emits `openDiff(string filePath)` when the header button or a file row is clicked. Parent's existing zero-argument QML handler still receives the signal; it must pass `filePath` to the new view to select that file.

## Native checkpoint renderer integration (2026-10-17)

`diff_review::execute` now registers one private opaque snapshot for an authorized historical range, alongside its existing bounded parsed result. Eligible text-hunk files share that snapshot ID; the raw native patch remains outside the Quickshell model. A renderer request supplies the chosen path, which must belong to the cached range. Many files in one range do not consume one cache slot each. Binary, missing and metadata-only changes retain their existing bounded text/metadata presentation, including file-mode details and pure-rename metadata.

Opening a historical file rechecks `orchestration:read`, rereads the saved exact native `getTurnDiff` or `getFullThreadDiff` request, validates thread/from/to identity and compares the raw patch hash. It never derives a checkout cwd, calls local Git, or calls `review.getDiffFileContents`. A changed/unavailable historical range fails explicitly. This follows native `DiffPanel.tsx:367-386,1214`: its full-file loader is provided only for checkout comparisons; historical runs use their stored patch. The shared pinned Pierre1.5.2 component receives no `loadDiffFiles` callback for checkpoints. No current-file contents are substituted for missing historical lines.

`T3DiffReview` now keys a renderer by both range snapshot and selected path, so moving between files in the same snapshot starts the correct file and closes the old session. Whitespace refetch, retry and expired-snapshot reload capture the current selected path before clearing the range. Closing invalidates pending reads and frees the renderer. The existing composer is not involved.

Native diff preferences are read from T3's canonical client-settings file: layout, initial word wrap, initial whitespace handling and file-collapse default. Layout selection persists with a fresh read followed by the existing revision-checked atomic writer, preserving other native fields. Visible failures require an explicit retry, which starts with another fresh read. Wrap/whitespace toggles remain view-local like native DiffPanel. The multi-file collapse behavior remains a separate layout gap; reading the default does not claim that behavior is implemented.
