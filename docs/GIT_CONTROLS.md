3. On explicit open/refresh, clear old `data` and error and set loading; send input to a bounded independent worker invoking `git_controls::execute(&environment,&input)`. 4. Worker receipt must copy the five input scope fields unchanged at the envelope top level, plus `result` or `error`. Call `scoped_result(expected,receipt)` before accepting. `None` means ignore a late response; `Some(Err)` means show the current request's failure. QML independently requires matching environment/thread/project/cwd/requestId and hides old rows/actions while loading or failed. Closing the popup invalidates the parent's expected scope and any in-flight response. QML data/scope changes cancel confirmation and selection.
5. QML receives `scope` and `view:{loading,error,data}`. Data is `{scope:{environment,thread,projectId,cwd,requestId,projectRoot,worktreePath},revision,status,scripts,actions}`. Status field names are native (`refName`, `isDefaultRef`, `workingTree.files[].insertions`, etc.), not older Git aliases. Script resolution is project settings override (including explicit `[]`), folded machine defaults, legacy project script override (`null` means defaults), aggregate project scripts if nonempty, then defaults.
6. Limits: 2,048 files, 256 scripts, 1 MiB serialized status/scripts/presentation, 8,192-byte paths, 65,535-byte script command, 10,000 UTF-16-unit commit message. Oversized or malformed results are errors, never silently truncated commit selections. HTTP/WS wire limits and timeouts remain those of the existing protocol connection; these local limits are checked after decoding and do not replace transport bounds. These are conservative adapter limits, not claims about native schema maxima. Required native booleans/counts, script icons/flags, duplicate script IDs/file paths and PR metadata are checked. Unknown optional fields are retained but not executed.

Read errors such as unavailable settings or Git status fail the combined read; no old scripts are treated as fresh. There is no background status subscription or automatic polling in this slice.

## Mutation/outbox contract: builders only

QML `actionRequested(intent)` emits `{scope,revision,operation,confirmed:true,defaultBranchConfirmed}` plus applicable `scriptId`, optional `commitMessage` and optional `filePaths`. It never supplies authoritative command text, cwd, terminal ID or a free-form RPC method. Parent must synchronously set `busy` when handling the signal to prevent a second submission before IPC returns.

Allowed operations are `commit`, `push`, `pull`, `create_pr`, `commit_push`, `commit_push_pr`, and `script`. Parent allocates a UUID `actionId` once per explicit submission, persists it with the existing outbox, and never normalizes a malformed supplied identifier. Keep each outbox record bound to environment/thread/project/cwd even if the user navigates elsewhere.

**Required dispatch sequence:**

1. Enforce native `AuthSourceControlWriteScope` (`source-control:write`) for Git mutations or `AuthTerminalOperateScope` (`terminal:operate`) for script open/write using the parent's actual authorization model (`packages/contracts/src/auth.ts:89-91`). Terminal observation additionally needs `AuthTerminalReadScope` (`terminal:read`). The QML booleans are presentation gates, not authorization; `canTerminalWrite` is a local UI property, not a native scope name. Keep it false until native terminal output observation is wired.
2. Keep the last accepted Rust-generated snapshot as the authoritative `current` (not a round-tripped UI JSON blob). Take the parent's per-checkout operation lock. Reread via `execute` immediately before enqueueing and pass that result as `fresh` to `build_verified_action(current,fresh,intent)`. Do not replace the popup's current snapshot before validating its intent, because confirmation captures its request identity. Any changed digest or scope requires a fresh user confirmation.
3. Dispatch only the returned plan's `steps` through existing management/write credential handling, **in order**, stopping on any failure. **Important correction from parent contract verification:** `git.runStackedAction` is an Effect **stream** (`packages/contracts/src/rpc.ts:1380-1385`), not a unary RPC. Use `Connection::subscribe`, correlate actionId/cwd/action on every event, and require native action_finished/action_failed before recording a terminal outcome. `build_action` / `build_verified_action` do not send anything. Never expose a generic unvalidated `rpc(tag,payload)` to QML.
4. `commit/push/create_pr/commit_push/commit_push_pr` produce one `git.runStackedAction` step with `{actionId,cwd,action,threadId,featureBranch:false}` and optional validated `commitMessage`/`filePaths`. Omitted message requests native message generation. Omitted paths means all changes; selected paths must be literal members of the freshly observed changed-file list, preserving whitespace. Empty explicit arrays and duplicate/unknown paths fail. No staging, discard, force-push, checkout or arbitrary Git arguments are added.
5. `pull` produces exactly `vcs.pull {cwd}`. It is enabled only for a named upstream-tracking branch behind but not ahead. Divergence requires native conflict resolution; no invented sync RPC. Commit alone can operate in detached HEAD as native menu behavior allows; remote/composite actions require a branch. Default-branch remote/composite actions require the second explicit default-branch acknowledgement; creating a feature branch is not implemented.
6. `script` selects the **authoritative resolved script by ID** and produces two steps: `terminal.open {threadId,terminalId,cwd,env,cols:120,rows:30,worktreePath?}` then `terminal.write {threadId,terminalId,data:script.command + "\r"}`. Runtime env is exactly project root plus optional worktree path. A fresh `term-ot3-script-<actionId>` session is used to avoid injecting into an existing busy shell. This is the native `preferNewTerminal` behavior, not native active-session reuse. Open must succeed before write; do not run both concurrently.
7. Parent must expose/observe **that returned terminal ID** using native terminal management (`terminal.attach`/native terminal UI). Existing O3 `terminal-open` command launcher is **not** a drop-in substitute: it chooses its own command-file terminal identity and does not consume this plan's `env`. Either wire the actual native terminal session into the frontend or open the native T3 terminal UI. No local subprocess script runner is supplied or permitted.
8. Treat native RPC acceptance as submitted, not script completion or Git success. A terminal write success only means command input delivery. Observe native terminal output and process state for execution; a persistent shell's status is not a script exit code. Retain operation receipt/progress in parent outbox. On transport disconnect/timeout after dispatch, set `operationState:"unknown"`, preserve action/session IDs, and do **not** replay the step. `retryAutomatically:false` is explicit in every plan; it is not a claim of server-side exactly-once execution. Partial open success followed by unknown write outcome must remain unknown. No rollback is attempted.
9. Refresh reads after known completion, and reconcile native result/toast/thread branch metadata through the parent's native workflow; this module does not invent success result schemas. `operationState:"pending"` / `"unknown"` locks submissions. `operationError` displays a parent-localized error. A fresh read alone does not prove a timed-out script was never submitted.

`revision` is SHA-256 of the bounded presentation content excluding `scope.requestId`, so a new read with the same status/scripts can verify the old confirmation. It is **not** a repository HEAD/content hash or server CAS. Same-stat file edits or external Git operations can race after the read; the native mutation contract has no expected-status/HEAD field. Do not claim atomic repository-state validation. Builders assume both snapshots came from Rust/native reads, not attacker-supplied presentation objects.
