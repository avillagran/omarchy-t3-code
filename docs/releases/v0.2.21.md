## Highlights

### Memory/Obsidian: one development vault on every computer

T3 keeps threads and decisions per environment and shares none of them between machines. Preferences → **Memory/Obsidian** sets up a shared development vault (a git repository of Obsidian notes) on the computer ot3 runs on, and keeps it in sync. See `docs/JOURNAL_VAULT.md`.

- **Finds the vault on your hosts.** Each connected environment is read (never written) for a vault set up there, by ot3 or by hand in its agent instructions. Clones of the same remote count as one vault; with several you choose. An offline host shows as unknown, not as having no vault.
- **Set up on this computer** clones the same remote here, even when the selected environment runs its agents on another host. It uses this computer's own sign-in (it explains `gh auth login` or an SSH key when one is missing) and never copies credentials. A bare repository on a host is reached over its SSH profile or OmaBridge.
- **Safe with existing folders.** A clone of the same remote is reused, with **Repair**; a folder with other files or another remote is never overwritten.
- **Agents on this computer** get a marked block in `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md`; the rest of those files is kept, and running the wizard again changes nothing.
- **Stays in sync**: pull when ot3 opens and when a thread starts, commit `journal(<project>)` and push when threads settle. A conflict stops the sync and keeps local commits. New T3 projects get their `Projects/<slug>/MEMORY.md`, and this computer is listed in `Machines.md`.
- **Open in Obsidian**, or how to install it when it is missing. The page says *ready* only when no step is pending.
- Without hosts: clone a remote by URL, or create a vault with a private GitHub repository.
- CLI: `omarchy-t3-client vault-status`, `vault-discover`, `vault-sync [--push]`.
