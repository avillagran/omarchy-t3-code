Native aarch64 and x86_64 packages for Omarchy on Arch Linux, with the Rust client and the Qt HTML preview frontend. Install or update with the README one-liner:

```bash
curl -fsSL https://raw.githubusercontent.com/avillagran/omarchy-t3-code/main/install.sh | bash
```

This release follows v0.2.15 (v0.2.16 was tagged but never published).

## Highlights

### Multi-purpose side panel

The panel next to the chat is no longer just a browser. The new side panel button opens tabs for:

- **Browser**: the preview browser, as before.
- **Renders**: HTML pages the agent renders in the chat, with a picker when there are several. Preferences can send new renders here instead of showing them inline.
- **Devices**: simulators and emulators from T3 Code (see below).

All tabs share one resizable slot. In narrow windows the panel opens as a sheet over the chat. `omarchy-shell io.github.avillagran.omarchy-t3-code sidePanel <browser|renders|devices>` opens a tab from scripts or keybindings.

### Simulators and emulators from T3 Code

The Devices tab connects to T3 Code's device support:

- It lists the simulators and emulators on your T3 environment's device hosts. Opening the tab refreshes the list, which installs or starts the device hub when needed, as in the T3 web app.
- **Start/Open** boots the device for the current chat and shows its screen in the panel. You can tap and swipe with the mouse, use the hardware buttons (Back, Home, Recents, Power) and type.
- **Close** only stops viewing. **Power off** ends the session and shuts the device down.
- iOS uses the simulator's MJPEG stream. Android decodes the emulator's H.264 stream with `ffmpeg` when it is installed, and otherwise falls back to periodic screenshots.

Tested against a live Android 14 emulator on a remote T3 environment.

### Smooth, adaptive animation

- **One shared clock.** The sky, spinners, the working shimmer and thread comets all run on one clock, so their frames coincide instead of adding up. Each animation runs only as fast as it needs: the idle sky drifts slowly, spinners and comets run at 60 fps, and shooting stars run at the display rate only while one is on screen.
- **Preferences > Animations > Animation smoothness** offers Adaptive (default), Saver (30 fps) and Maximum.
- **Threads changing section fly to their new place.** When a thread moves between Working, Ready, Snoozed and Settled, it travels there and the rows around it slide out of the way. The motion style (Swoop, Glide, Fade or Off) and its speed are configurable.
- **Smoother indicators.** The spinner is now a continuous arc, the "working" shimmer sweeps continuously, and the draft saved/saving state cross-fades. The thread state icons animate when they change.
- **Bar indicator styles.** Choose Orbit, Scanner, Equalizer, Heartbeat, Ticks or Living logo. The indicator is coloured by error, pending question or work, and moves only while a thread works. The bar no longer redraws at the display rate.
- **Frame rate meter** (Preferences > Animations). It separates ambient motion from real drops.

### Faster scrolling and streaming

- Streamed messages no longer re-serialise the whole conversation on the UI thread: about 0.7 ms per update instead of about 7.9 ms on a long chat.
- Conversation rows build only the card they show. Each row was about three times slower to create, and its hidden cards re-ran their bindings on every scroll frame.
- The detached window uses an opaque surface on opaque themes, so Hyprland skips drawing and blurring what lies behind it.
- Keyboard shortcut resolution is cached per focus state.

## Fixes

- New chats inherit the permissions of the chat that is open. The project default no longer overrides them.
- HTML renders that arrive while a chat is open now appear. Before, they only showed after reloading the chat.
- Device state from T3 with empty optional fields no longer fails as invalid once device support is turned on.

## Notes

- `ffmpeg` is optional. It only makes Android emulator screens smooth.
- On device hosts, start the T3 server with a modest open-file limit, for example `ulimit -n 524288`. With a very large limit, which an SSH-launched server can inherit, the Android emulator hangs and crashes before it comes online.
- Diagnostics: `profileScroll`, `profileResult` and `skyState` IPC commands (see `docs/DEVELOPMENT.md`).
