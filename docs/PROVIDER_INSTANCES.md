# Provider instances in native preferences

Preferences → Providers manages instances on the selected T3 Code environment. The same Add provider → Identity → Config wizard offers every built-in driver in the pinned T3 client registry: Codex, Claude, Cursor, Grok, OpenCode, Antigravity, Muse Code, Pi, and ACP Registry. Instance lists also retain unfamiliar driver kinds already configured on a server. Choose the **owning environment** first; neither credentials nor account settings are copied between hosts.

Instance creation, updates, enablement and removal use T3's atomic `server.updateSettings` `providerInstanceMutation` contract rather than replacing the full provider map. The native view exposes only whitelisted, non-secret driver configuration, public status and masked environment variables. Mutations require the selected server's `providers:manage` scope. A read-only session cannot alter instances. Sensitive environment values remain on the server and are retained by name when editing other fields; the view never reads their value. Codex and Claude retain their default slots.

For a separate Claude subscription, create a Claude instance with a distinct `CLAUDE_CONFIG_DIR path`, and sign in with Claude Code using that directory on the owning machine. A custom Codex account uses its own `CODEX_HOME path`/shadow home. Other drivers expose their own applicable fields. ACP Registry supports manual local executable and registry agent ID configuration; the full upstream registry discovery/install and in-app provider sign-in workflows are still separate work. The native environment-variable form supports per-instance names, values and sensitive flags; users should keep secret values marked sensitive.

Definitions are pinned to upstream commit `5a4e9980533705774dc3f45b35cacf76c3d78dbc` in `data/provider-drivers.json`. Validate with `cargo test --release --test provider_instances` and `WAYLAND_DISPLAY=wayland-1 QT_QPA_PLATFORM=wayland tools/test-qml provider-instances`. Fixtures use synthetic accounts only.
