# Native voice host bridge

The dedicated `voice-watch` process owns the original consent producer, native
Chromium capture and cancellable SDK transports. An ordinary application-watch
restart cannot re-execute this owner during recording. Missing admitted resources
leave the main application usable and report voice unavailable. Runtime/addon
paths are trusted startup configuration, never voice action parameters.

Qt uses the same realm-local primitives for the complete original controller and
browser platform. Every controller gets its own immutable capture facade. Late
stop/release callbacks from a disposed editor cannot take a successor's capture.
The GUI receives metadata and opaque recording IDs; PCM, credentials, media URLs
and stream tickets stay with their native owners. Buffered retry keeps the same
recording/options/owner and does not prepare another microphone.

Preparation runs the complete original speech codecs and the complete selected
client-setting field properties, including decoding defaults. Original callback
bodies capture vocabulary, correction cues, draft environment and cleanup grant.
The cleanup request uses the original bounded draft-context producer. A changed
cleanup identity refuses optional cleanup without failing audio preparation or
retargeting the transcript. Invalid or unrepresentable payloads fail explicitly.
Successful JavaScript decoding does not claim Rust can represent lone UTF16
surrogates in every options/transcript field.

The generated Qt preference module uses standard Babel object-spread lowering.
Three original vocabulary `flatMap` call sites link to a realm-local primitive
for admitted ordinary metadata arrays. It preserves immediate mapper/flatten
ordering, holes and throw order without modifying global constructors or
prototypes. Custom species, proxies and arbitrary array-like objects are outside
that metadata boundary. Original dictionary resolution is unchanged.

Ordinary preference writes validate with that original codec before the existing
client-settings CAS writer. Only explicitly patched voice fields change; unknown
settings remain intact and a stale revision refuses the save. Audio and cleanup
grants remain in their separate original storage namespace. A common preference
save cannot restore either grant.

The consent socket has one persistent reader and bounded reply/event channels.
Unsolicited storage changes reach the host while no RPC is active. Guards still
query the current original producer; a queued historical snapshot is observational.
Qt also fences snapshot Promise delivery against newer notifications. Availability
loss stops admission while retaining cleanup routing through the surviving owner.

Requests retain their generation and cancellation token until their actual
terminal event. Capture cancellation retires network ownership first. Stop drains
PCM; microphone release must be Confirmed before the separate stream finish.
Unknown cleanup remains sticky. Capture/stream callbacks retain only weak host
and session references, and final owner drop cancels transports before resource
destruction can wait on helpers or processes.

The lazy private display has its own persistent spawning thread. On Linux,
`PR_SET_PDEATHSIG` follows the thread that created the child, so a short-lived
action thread cannot own Xvfb safely. The display owner retains the actual child
pidfd and stays alive through the last capture lease and display exit before
joining. The child-death guard and existing native deadlines remain intact.
See the [Linux manual](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html).

## Evidence and remaining acceptance

- `voice-preferences-oracle-gua55m3y`: 102 identical Node-original/Qt observations
  for dictionary aliases/NFC, UTF16 hint limits, cleanup context and callbacks,
  plus ordinary-array order/hole/mutation/throw cases. This does not establish
  equivalence across the complete Unicode universe or every JavaScript object.
- `native-voice-host-r9qry3m7`: nine real Qt controller/platform/bridge scenarios
  with an explicit synthetic metadata peer. They cover buffered/streamed flow,
  cleanup, permission denial, retained retry, stale events, confirmed disposal,
  unavailable-owner cleanup, snapshot ordering and deferred predecessor release.
- `voice-host-bridge-build-20261107-v4`: combined all-target strict check and
  actual client build with the public SDK and source-matched Wayland modules.
  Later preference/display changes require their own final source checks.
- `voice-host-process-av7lnkeg`: real Chromium capture yields 36,684 nonzero,
  finite synthetic PCM bytes through the actual SDK/private HTTP peer, plus one
  cleanup request. Deferred permission cancellation/reacquisition, duplicate and
  reused request IDs, never-owned release, stale cloud ACK during recording,
  owner ABA, missing draft defaults and unsolicited consent pass. Both explicit
  shutdown and last-owner Drop leave no other process in the private namespace.
- `voice-consent-process-kihh0b3z`: seven process scenarios plus idle demux,
  original codecs, canonical legacy UTF16 cleanup identity and preference CAS
  assertions pass. Strict all-target compilation passes on this complete source.
- Earlier display-start failures are retained. After fixing the persistent
  spawner, the PID1 fixture still adopted six defunct Chromium descendants.
  Independent categorical process inventory proved there were no live children;
  the final runner uses private init and checks the complete namespace, retaining
  the earlier failed assertion instead of relabeling it.

`tests/fixtures/voice-host-bridge-proof-4314.json` records the full matching
source maps, immutable artifacts, receipts and limits for these separate checks.

Direct Qt → QProcess → the production stdio parser → Host → SDK now passes
`voice-watch-qt-fb_2y6yd`: 34,080 actual synthetic PCM bytes, one real permission,
original state progression and draft insertion, clean stdin-EOF shutdown and no
remaining private process. The fixture constructs typed synthetic resources only
inside its private container; production adds no fake-device environment flag.
The parser/emitter bytes are unchanged by moving them into the shared library
entrypoint. Its all-target strict check and source maps are separate from the
pre-refactor Host/consent/CLI receipts, whose original hashes remain qualified.

Actual mounted QML controls and permission/shortcut behavior have their separate
transport-only UI receipt in `NATIVE-VOICE-UI-4314.md`. Packaging/resource discovery, stable microphone
enumeration, cloud key save/ack, the real optional cleanup provider and complete
transport UTF16 fidelity remain product gaps. No installation, automatic grant
or live provider request is implied by the isolated tests above.

The voice UI adds 70 English source keys and 1,330 translations across the 19
other supported locales, including the original controller's static error and
warning messages. The private pinned-Node full catalog check passes for all
20 × 2,257 keys with no warnings. Rebuilding also restores two existing model/draft
strings to a source batch using their exact prior catalog values; every previous
translation stays unchanged. Provider-supplied free-form reasons remain data.
